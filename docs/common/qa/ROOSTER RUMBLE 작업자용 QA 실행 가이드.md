# ROOSTER RUMBLE 작업자용 QA 실행 가이드

- 기준 문서: `ROOSTER RUMBLE QA 체크리스트.md`
- 정리 기준: 2026년 10월
- 목적: 확정된 방향, 시연 확인 항목, 추후 검토 항목을 구분해 제작·QA 작업과 확인 기준을 빠르게 파악한다.

## 1. 먼저 볼 우선순위

1. **판정·베팅 안정성**을 우선 확인한다. 시연 그래픽은 피드백을 받기 위한 단계다.
2. **Derby Race와 Rumble Pit 모두** 테스트 가능한 빌드로 준비한다. 선호 모드는 실제 현장 테스트 후 판단한다.
3. 확인이 필요한 연출은 완성품으로 단정하지 말고 **비교 가능한 샘플**을 준비해 시연한다.
4. 1차 업데이트에 반영한 항목과 미반영 항목을 목록으로 정리해 사전 공유한다.
5. 기준 문서의 회의 아이디어는 모두 확정된 개발 요구사항이 아니다. 아래 상태 표기를 기준으로 작업 범위를 판단한다.

## 2. 상태 표기

| 표기 | 의미 | 작업자 조치 |
|---|---|---|
| **확정** | 적용 방향이 결정됨 | 구현하고 QA 기준으로 확인 |
| **샘플 확인** | 방향은 제안됐으나 최종 강도·범위 미정 | 비교 샘플을 준비하고 시연 피드백 기록 |
| **테스트 후 결정** | 실제 빌드/사용자 테스트가 필요 | 테스트 결과와 권고안을 함께 제출 |
| **후속 검토** | 초기 범위에서 제외하거나 운영 후 판단 | 별도 승인 전에는 출시 필수 항목으로 잡지 않음 |

## 3. 공통 실행 항목

### 시스템·일정

- [ ] 경기 판정 결과가 일관되고, 결과·배당 계산 및 지급 흐름이 안정적인지 확인한다.
- [ ] 경주 길이를 **1분 이상**으로 조정한다. (기준 문서의 이전 약 30초 언급보다 이후 피드백의 1분 이상 기준을 우선 적용)
- [ ] 두 모드의 테스트 빌드를 준비하고, 현장/오프라인 테스트에서 모드 선호도와 이탈 지점을 기록한다.
- [ ] 업데이트 일정은 기준 문서 작성 시점의 상대 일정이므로, 실제 1차 업데이트 날짜와 피드백 회의 일정을 다시 확정한다.
- [ ] 업데이트별 반영 완료·진행 중·보류 항목을 정리해 시연 전에 공유한다.

### 사용자 가독성·접근성

- [ ] 핵심 UI 텍스트를 현행보다 크게 조정한 시안을 준비한다. 기준 문서는 약 2배 확대를 제안한다.
- [ ] 기본 크기 외에 사용자가 글자 크기를 조절하는 옵션을 마련한다.
- [ ] 모바일 화면과 매장 대형 화면에서 베팅 정보, 결과, 타이머, 선수 식별이 잘 보이는지 확인한다.
- [ ] 경기 진행 중에는 불필요한 상태 표기를 띄우지 않고, 경기 시작 전 선수 정보와 기록을 제공한다.

## 4. Derby Race — 경주 모드

### 확정된 방향

| 작업 영역 | 구현 방향 |
|---|---|
| 비주얼 | 캐주얼 카툰풍으로 통일 |
| 트랙 환경 | 비·바람·온도를 경기 변수로 활용. 눈이 쌓인 트랙은 제외 |
| 경기 시간 | 1분 이상 |
| 모션 | 출발 대기 동작과 질주 모션을 세분화해 1차 업데이트 샘플에 반영 |
| 레이스 중 컨디션 표시 | 경기 중 실시간 상태 표시는 제외. 관련 정보는 경기 전 제공 |
| 미니맵 | 현재 화면 하단의 가로형 배치를 기본 유지 |
| 추월 표시 | 순위 변경을 알아볼 수 있는 중간 강도의 미세 발광 효과 |
| 피니시 | 경기 종료 후 짧은 하이라이트/슬로우 리플레이. 경기 도중 슬로우 금지, 스킵 제공 |
| 중계 | 현재 보이스 기반 유지, 더 빠른 템포와 출발·접전·결승의 고저 적용 |
| 기기 목표 | 갤럭시 S20급을 기준으로 최적화 후 최소·권장 사양 제안 |

### 샘플 또는 테스트로 결정할 항목

| 항목 | 준비·확인할 내용 |
|---|---|
| 트랙 재질·색 대비 | 흙/모래와 잔디 트랙 시안을 비교하고 닭 캐릭터 식별성 및 성능 확인 |
| 날씨·시간대 | 환경 변화가 레인별 선수 식별과 관전에 방해되지 않는지 확인 |
| 주행 이펙트 | 가속 스피드 라인 중심의 샘플을 준비. 잔상·바람 궤적은 우선 제외하고 시야 방해 여부 점검 |
| 레인 침범 | 장거리 경주 샘플로 경합 재미와 예측 가능성을 함께 확인. 혼전 중 번호/선수 식별이 되는지 확인 |
| 카메라 | 안정적인 기본안과 더 역동적인 안을 비교. 특히 대형 화면에서 흔들림·멀미 여부 확인 |
| 리플레이 정보 | 구간 속도·추월 정보 등을 적용해 내부 검토 후 사용자 노출 범위를 결정 |
| 경기 전 정보 | 주행 유형, 능력치, 과거 기록을 한 화면/정보지에서 읽고 비교할 수 있는지 확인 |

### 경주 QA 통과 체크

- [ ] 출발 전부터 결승까지 선수 번호를 계속 식별할 수 있다.
- [ ] 추월·순위 변경을 미니맵과 실제 화면에서 모두 알아볼 수 있다.
- [ ] 환경 효과와 카메라 연출이 경기 결과를 가리거나 결과 조작처럼 보이지 않는다.
- [ ] 종료 후 리플레이는 짧고 건너뛸 수 있으며, 배당 결과 화면으로 정상 이동한다.
- [ ] 최소 사양 후보 기기에서 프레임 저하, UI 겹침, 입력 지연을 확인하고 모델명을 기록한다.

## 5. Rumble Pit — 격투 모드

### 확정된 방향

| 작업 영역 | 구현 방향 |
|---|---|
| 캐릭터·경기장 | 경주 모드와 어울리는 카툰풍, 깔끔한 아케이드 경기장 |
| 전투 | 실제 투계 재현보다 게임형 대전 액션의 공방을 강조 |
| 타격 효과 | 아케이드 섬광·스파크 중심 |
| 큰 타격 혈흔 | 크리티컬에 한해 짧게 화면에 나타났다 사라지는 효과. 신체의 지속적인 상처·출혈 묘사는 제외 |
| 관전 카메라 | 객관적인 관전 시점 유지. 히트스톱과 급격한 딥 다이브 줌인은 제외 |
| 그로기 | 짧게 허용하되 경기 템포를 늦추지 않음. 다운 카운트·재기립 연출은 제외 |
| 판정 | 다운 발생 시 즉시 경기 종료(KO) |
| 베팅 | 오픈 초기에는 경기 전 사전 베팅만 노출 |

### 샘플 또는 후속 검토

| 항목 | 준비·확인할 내용 |
|---|---|
| 카메라 움직임 | 줌인·줌아웃/앵글 전환 샘플을 시연해 몰입도와 피로도를 확인한 뒤 확정 |
| 방어·특수 효과 | 기본 동작과 구분되는지, 1차 업데이트 이후 적용 범위를 확인 |
| 중간 베팅 | 초기 출시 범위에서 제외. 사용자 반응과 형평성 검토 후 별도 결정 |

### 격투 QA 통과 체크

- [ ] 공격 적중과 방어 상태를 화면만 보고 구별할 수 있다.
- [ ] 타격 연출이 승패 판정 순간을 가리거나 경기를 멈춘 것처럼 보이지 않는다.
- [ ] 혈흔 효과는 큰 타격에서만 짧게 나타나며 신체에 남지 않는다.
- [ ] 그로기 시간이 길어지지 않고, 다운 판정 후 결과 화면으로 즉시 전환된다.
- [ ] 카메라 전환이 선수·경기 상황을 놓치게 하거나 어지러움을 유발하지 않는다.

## 6. 공통 정보·사운드·현장 확인

- [ ] 경기 전 가이드/정보 화면에서 선수의 기록·능력치·주행 또는 전투 특성을 이해할 수 있다.
- [ ] 통계는 정확하고 일관되게 표시한다. 확률·판정·결과를 오해하게 하는 표기나 연출은 넣지 않는다.
- [ ] 중계 템포는 기본보다 빠르게 조정하고, 출발·접전·결승에서 음량과 에너지가 자연스럽게 고조되는지 확인한다.
- [ ] `ROOSTER RUMBLE`, `Derby Race`, `Rumble Pit` 이름 체계는 유지하는 방향으로 정리한다.
- [ ] 기기 기준은 시연 빌드 측정 결과로 최소/권장 사양을 확정하고, 미지원 기기에 안내가 필요한지 확인한다.

## 7. 초기 범위에서 분리할 회의 아이디어

아래는 원본 문서의 추가 논의 의견이다. 확정된 제작 요구사항과 섞이지 않도록 별도 승인·검토 후 진행한다.

- 농장/닭 육성 콘텐츠: 경주·격투 핵심 모드 완성 이후 검토.
- 현장 프로모션 및 경품 행사: 운영·예산·필요한 외부 검토를 거쳐 별도 계획으로 확정.
- 베팅 관련 법률·시장 적합성 주장: 원본의 의견만으로 결론 내리지 말고, 대상 지역 기준으로 별도 확인.
- 과거 기록이나 환경 정보를 활용한 이용자 분석 기능: 실제 데이터와 규칙을 정확히 설명하고, 존재하지 않는 패턴을 암시하거나 결과를 오해하게 만드는 방식은 작업 요구사항으로 채택하지 않는다.
- 경주 중간 베팅·추가 베팅: 초기 출시에서 비활성화. 후속 도입은 형평성과 운영 기준을 확정한 뒤 진행.
- 매장용 태블릿/터치스크린 제공: 운영 대안으로만 기록하고 별도 비용·운영 검토.
